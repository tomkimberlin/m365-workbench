# Mouse-wheel and primary-user corrections — 2026.09.29

## Changes

- Mouse-wheel input resolves the current DataGrid ScrollViewer for every event. The previous indefinitely cached visual child could survive a template rebuild, swallow wheel events, and move an invisible old viewer while the visible scrollbar still worked. Events remain unhandled when no scrollable viewer is available. No sleep hooks, global input hooks, or changes to virtualization are needed.
- Primary-user labels, detail emails, sorting, and search now use the Intune managed-device `/users` relationship, not device-level enrollment-user fields. Successful empty assignments show **Unassigned**. Unresolved assignments are not assumed empty, and restricted user details cannot become an enrollment-user fallback.
- Assignment reads are grouped in Graph batches of at most 20 GET requests, correlate out-of-order responses by request ID, and complete relationship pagination before publishing inventory. Batch subrequest failures preserve their HTTP status and use the existing refresh-error path, retaining previous inventory. Refresh cancellation still runs through the background worker.
- Pagination is restricted to the original managed-device relationship on Microsoft Graph, with cycle and page-count limits. Missing, malformed, duplicate, or unmatched responses cannot be published as successful empty assignments.

## Verification

The synthetic WPF regression repeatedly rebuilds the actual DataGrid template and exercises the production wheel handler. It also checks scrolling after filtering, upward movement after direct scrolling, non-scrollable lists, zero-delta input, and bottom bounds.

Primary-user tests cover assigned, unassigned, different enrollment identity, partial user details, multiple users, missing assignment data, batch size/deduplication, out-of-order results, pagination, malformed responses, HTTP failures, and unsafe next-page links. Demo data uses explicit synthetic assignments.

All 272 offline checks passed on both bundled PowerShell 7.6.5 and installed Store PowerShell 7.6.6, including the existing off-screen visual previews and security-boundary checks.

Read-only live verification confirmed that a device with populated enrollment fields but no primary-user relationship now displays Unassigned with a blank primary-user email. No tenant assignments, authentication policies, secrets, or local verification settings were changed. Tenant-specific evidence is deliberately excluded from this repository.

## Limits

The stale-viewer failure was reproduced deterministically by rebuilding the visual template. The specific Windows event behind the reported long-running/sleep-resume incident was not captured. Existing windows must be reopened to load the corrected wheel handler. Previously investigated native PowerShell process crashes remain a separate issue.
