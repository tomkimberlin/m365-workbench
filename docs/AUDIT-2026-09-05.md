# Audit and hardening — 2026-09-05

Scope: local source review, recovery/authentication boundaries, clipboard handling, Windows lifecycle integration, startup behavior, and UI responsiveness. This was not a penetration test or a live-tenant administrative exercise. No real recovery material was requested.

## Fixed

| Area | Finding and correction |
| --- | --- |
| Clipboard ownership | Ownership was sampled after releasing the native clipboard lock, which could claim a newer item from another application. Sample it before release; require a valid owner window and attach exclusion formats before plaintext. |
| Clipboard cleanup | Busy cleanup could be treated as replacement and lose its retry state. Preserve ownership/metadata, retry, keep secret-hiding timers running, and defer normal closing when cleanup is still blocked. Authentication completion uses the same retry path. |
| Windows session changes | A PowerShell callback attached to a background SystemEvents thread could lack a runspace. Receive lock/logoff/disconnect messages through the WPF window procedure on the UI thread instead. |
| Recovery identity | LAPS did not validate the returned device ID; BitLocker checked the device but not the selected key-record ID. Validate both requested identities before returning a secret. Release response secret fields on success and failure, including unselected LAPS credentials. |
| Verification results | An existing grant could override an explicit failed/canceled local result in the decision helper. Explicit outcomes now take precedence. |
| Expiry | Clipboard/reveal deadlines used the adjustable wall clock. Anchor those deadlines to a stopwatch; the existing verification deadline remains monotonic. |
| Inventory pagination | Page links were followed without host or cycle checks. Allow only HTTPS Graph v1.0 links on the default port, reject credentials/fragments, detect cycles, and bound the number of pages. |
| Payload format | BitLocker format validation accepted Unicode digits and a final newline. Require precisely eight six-digit ASCII groups. This is format validation, not a mathematical or live-device recovery test. |
| Preview safety | Preview rendering could be requested without demo mode. Reject it before loading tenant configuration or authentication. |
| Startup and UI | Support machine-installed, Store, and PATH PowerShell; show a safe startup error instead of silently failing behind a hidden console; identify the build in the title; debounce search and cache inventory totals. |

## Verification

- The original 119 checks passed before editing.
- Expanded offline checks run the actual LAPS, BitLocker, and inventory operation bodies against synthetic responses, including malformed IDs/payloads and unsafe/repeated page links.
- The real clipboard algorithm is compiled against deterministic native-call shims to exercise replacement races, protection-format ordering, and ownership retention under contention without touching the user's clipboard.
- The production UI timer is exercised with a busy clipboard to verify retry scheduling and independent secret hiding. Synthetic Windows session messages exercise revocation without locking the workstation.
- The suite builds the GUI launcher, verifies shortcut identity, and renders both the workspace and Microsoft-verification overlay with fictional demo data. Test artifacts live outside the repository and are cleaned up.

## Remaining limits

Live tenant permissions, Conditional Access, physical PIN/biometric prompts, and end-to-end recovery against a real device were not re-tested in this audit. Native clipboard races are covered by shims, not an adversarial multi-process Windows stress test. Memory clearing and third-party clipboard readers remain subject to the [local security boundary](../SECURITY.md#local-security-boundary). National-cloud Graph endpoints are not supported by the current configuration.
