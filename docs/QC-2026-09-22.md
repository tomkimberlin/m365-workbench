# Quality review — 2026-09-22

Scope: recovery-panel layout, inventory/filter responsiveness, empty/error states, and recovery-cache lifetime. This review used local source inspection, real WPF layout, and synthetic offline fixtures. No live recovery values were requested or production screenshots published.

## Corrections

- Both recovery-status rows now give their text a finite width, allowing countdowns and cleanup messages to wrap. The previous horizontal container measured its children with unlimited width, defeating text wrapping. Long administrator and volume labels also wrap; unusually long sign-in labels are bounded with the full value available as a tooltip.
- Inventory filtering snapshots the search and filter controls once per refresh instead of once per row. Inventory totals are counted in the collection-building pass, and selection restoration avoids an extra materialized copy of the filtered view.
- A successful zero-device inventory is accepted and displays the normal empty state. Previously, mandatory array-parameter validation rejected an empty collection before the UI could handle it.
- Cached LAPS and BitLocker actions now compare their deadlines against the same elapsed-time clock used to create and expire them. Windows clock adjustments cannot affect cache reuse decisions.
- Authentication failures and Graph 401 responses revoke local verification, hide cached/displayed secrets, and disable recovery actions until sign-in succeeds. Other request errors retain the existing retry behavior.

## Verification

- All 188 offline checks passed locally after the changes.
- The complete offline suite includes actual WPF layout assertions for both recovery panels at 1100, 1280, and 1600 pixel logical widths, with enlarged status text and countdown, cleared, and busy-cleanup messages.
- Actual production action functions are tested against simulated clocks that differ from wall time. The production operation-completion path is exercised with a synthetic Graph 401 response.
- Inventory tests cover Entra-only disappearing during refresh, independent no-match searches, a completely empty inventory, recovery from empty, 5,000-row search/count correctness, and retained selection.
- Synthetic LAPS and BitLocker clipboard-status previews were rendered and visually checked. Preview state does not retrieve secrets or write to the clipboard.
- One same-machine 5,000-row comparison measured inventory binding/filtering at 287 ms before versus 103 ms after, and search at 78 ms before versus 41 ms after. These are local smoke measurements, not network timings or performance guarantees; timing is reported but not used as a flaky pass/fail threshold.

## Limits

This is not a live-tenant permission, authentication-policy, or real-device recovery test. It does not establish a fix for previously observed native PowerShell/runtime process crashes. The security and platform limitations recorded in the [earlier audit](AUDIT-2026-09-05.md#remaining-limits) still apply. Local verification settings are not changed by this update.
